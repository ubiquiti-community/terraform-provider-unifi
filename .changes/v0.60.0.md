## [v0.60.0] - 2026-10-26

One breaking change and the fixes that followed it. The headline is the
attribute nesting shipped as v0.60.0-beta.0 on 2026-10-07: groups of flat,
prefix-named attributes across sixteen resources and data sources become
nested objects. Every resource involved bumps its schema version and ships a
state upgrader, so state migrates on the next plan, but **configuration must
change**; the full mapping is below.

Also in this release: assisted roaming on `unifi_wlan` for Network 10.x; a
refresh fix for resources deleted outside Terraform, which failed every plan
with `Missing Resource Identity After Read` on CLIs without resource identity
support (OpenTofu < 1.12, Terraform < 1.12); and three fixes measured on
Network 10.0.x controllers for `unifi_network` and `unifi_setting`.

### ✨ Features

- **`unifi_wlan`: `roaming_assistant_na` and `roaming_assistant_6e`.** UniFi Network 10.x moved assisted roaming from the device's radio table to the WLAN; these nested objects (`enabled`, `rssi`) replace the deprecated device-level `radio_table.assisted_roaming_*` attributes.

### ⚠️ Breaking Changes

- **Prefixed attributes are now nested objects across resources and data sources.** Groups of flat, prefix-named attributes (`lcm_idle_timeout`, `stormctrl_bcast_level`, `ipv6_ra_priority`, …) have been bundled into nested attributes (`lcm = { idle_timeout = … }`, `stormctrl = { bcast = { level = … } }`, `ipv6 = { ra = { priority = … } }`). Every resource involved bumps its schema version and ships a state upgrader, so existing state migrates automatically on the next plan; only configuration needs to change. Leaf names, types, validators and defaults are unchanged (with the exceptions called out below), and `HH:MM` clock times are now validated. The full mapping:
  - `unifi_device` (schema v3): `led_override`/`led_override_color`/`led_override_color_brightness` → `led = { override, color, brightness }`; `stp_version`/`stp_priority` → `stp = { version, priority }`; `lcm_*` → `lcm = { brightness, brightness_override, idle_timeout, idle_timeout_override, night_mode = { begins, ends } }`; inside `port_override`: `dot1x_*` → `dot1x = { ctrl, idle_timeout }`, `egress_rate_limit_kbps[_enabled]` → `egress_rate_limit = { enabled, kbps }`, `lldpmed_*` → `lldpmed = { enabled, notify_enabled }`, `port_security_*` → `port_security = { enabled, mac_address }`, `stormctrl_*` → `stormctrl = { type, bcast = { enabled, level, rate }, mcast = {…}, ucast = {…} }`.
    Inside `port_override`, the value leaves of these groups (`dot1x.ctrl`, `dot1x.idle_timeout`, `egress_rate_limit.kbps`, `port_security.mac_address`, `stormctrl.type` and every `level`/`rate`) are now Optional+Computed rather than Optional-only, so a partially declared group (e.g. `dot1x = { ctrl = "auto" }`) resolves its undeclared leaves from the controller instead of forcing them to null.
  - `unifi_port_profile` (v2): the same `dot1x`, `egress_rate_limit`, `lldpmed`, `port_security` and `stormctrl` objects as `port_override`. `egress_rate_limit`, `port_security` and `stormctrl` are now actually written to and read from the controller (they were previously accepted but never sent); their value leaves are computed from the controller when unset, so disable a feature with `enabled = false` rather than by removing the block.
  - `unifi_wlan` (v2): `wpa_mode`/`wpa_enc` → `wpa = { mode, enc }`; `wpa3_*` → `wpa3 = { support, transition, fast_roaming, enhanced_192 }`; `radius_profile_id`/`radius_mac_auth_enabled` → `radius = { profile_id, mac_auth_enabled }`; `ap_group_ids`/`ap_group_mode` → `ap_group = { ids, mode }`; `schedule[].start_hour`/`start_minute` → `schedule[].start = { hour, minute }`. Following the v0.59.0 fixes, `wpa3.support`, `wpa3.transition` and `wpa.enc` carry no static default and are taken from the controller when unset, so the `wpa` and `wpa3` groups are planned from `ModifyPlan` rather than a schema `Default`.
  - `unifi_firewall_rule` (v1): `src_*` → `source = { network_id, network_type, firewall_group_ids, address, address_ipv6, port, mac }`; `dst_*` → `destination = { … }`; `icmp_typename`/`icmp_v6_typename` → `icmp = { typename, v6_typename }`; `state_*` → `state = { established, invalid, new, related }`.
  - `unifi_firewall_policy` (v2): `icmp_typename`/`icmp_v6_typename` → `icmp = { typename, v6_typename }`; `schedule.time_all_day`/`time_range_start`/`time_range_end` → `schedule.time = { all_day, range = { start, end } }`.
  - `unifi_site_to_site_vpn` (v2): `ike_*` → `ike = { encryption, hash, dh_group, lifetime }`; `esp_*` → `esp = { … }`.
  - `unifi_client_qos_rate` resource (v1) and data source: `qos_rate_max_down`/`qos_rate_max_up` → `qos_rate = { max_down, max_up }` (matching `unifi_client.qos_rate`).
  - `unifi_static_route` (v1): `gateway_device`/`gateway_type` → `gateway = { device, type }`.
  - `unifi_client_info`, `unifi_client_info_list` and `unifi_client_list` data sources: `network_id`/`network_name` → `network = { id, name }`; `last_uplink_*` → `last_uplink = { mac, name, remote_port }`; `last_connection_network_*` → `last_connection_network = { id, name }`; `tx_rate`/`tx_bytes` → `tx = { rate, bytes }`; `rx_rate`/`rx_bytes` → `rx = { rate, bytes }`.
  - `unifi_network` (v2) and data source: `ipv6_*` → `ipv6 = { interface_type, client_address_assignment, static_subnet, aliases, ra = { enabled (was ipv6_ra), priority, preferred_lifetime, valid_lifetime }, pd = { interface, prefixid, start, stop, auto_prefixid_enabled } }`; `dhcp_server.dns_enabled`/`dns_servers` → `dhcp_server.dns = { enabled, servers }`; `dhcp_server.ntp_enabled`/`ntp_servers` → `dhcp_server.ntp = { enabled, servers }`; `dhcp_v6_server.dns_auto`/`dns_servers` → `dhcp_v6_server.dns = { auto, servers }`; data source only: `wan_*` → `wan = { dns, egress_qos, gateway, gateway_v6, ip, netmask, network_group, type, type_v6, username }`.
  - `unifi_setting` (v2): `usg.tcp_*_timeout` → `usg.tcp = { close_timeout, close_wait_timeout, established_timeout, fin_wait_timeout, last_ack_timeout, syn_recv_timeout, syn_sent_timeout, time_wait_timeout }`; `usg.udp_*_timeout` → `usg.udp = { other_timeout, stream_timeout }`; `usg.upnp_*` → `usg.upnp = { enabled, nat_pmp_enabled, secure_mode, wan_interface }`; `usg.geo_ip_filtering_*` → `usg.geo_ip_filtering = { block, countries, enabled, traffic_direction }`; `usg.offload_*` → `usg.offload = { accounting, l2_blocking, sch }`; `mgmt.ssh_*` → `mgmt.ssh = { enabled, keys, username, password, auth_password_enabled }`; `mgmt.auto_upgrade`/`auto_upgrade_hour` → `mgmt.auto_upgrade = { enabled, hour }`; `syslog.netconsole_*` → `syslog.netconsole = { enabled, host, port }`; `syslog.this_controller`/`this_controller_encrypted_only` → `syslog.this_controller = { enabled, encrypted_only }`; `ips.suppression_whitelist`/`suppression_alerts` → `ips.suppression = { whitelist, alerts }`.
  - `unifi_radius_profile` resource (v2) and data source: `interim_update_enabled`/`interim_update_interval` → `interim_update = { enabled, interval }`; `vlan_enabled`/`vlan_wlan_mode` → `vlan = { enabled, wlan_mode }`.
  - `unifi_radius_user` resource (v1, shared with the deprecated `unifi_account`) and data source: `tunnel_type`/`tunnel_medium_type`/`tunnel_config_type` → `tunnel = { type, medium_type, config_type }`. Moving a v0 `unifi_account` into `unifi_radius_user` still works (`moved` blocks).
  - `unifi_vpn_server` (v1): `openvpn.ca_crt`/`ca_key` → `openvpn.ca = { crt, key }`; `openvpn.server_crt`/`server_key` → `openvpn.server = { crt, key }`; `openvpn.shared_client_crt`/`shared_client_key` → `openvpn.shared_client = { crt, key }`.
  - `unifi_wan` (v1): `wan_dslite_remote_host`/`wan_dslite_remote_host_auto` → `dslite = { remote_host, remote_host_auto }`; `dns.ipv6_primary`/`ipv6_secondary`/`ipv6_preference` → `dns.ipv6 = { primary, secondary, preference }`; `dhcpv6.pd_size`/`pd_size_auto` → `dhcpv6.pd = { size, size_auto }`.
  Groups that mix a static default with controller-computed leaves (`unifi_network.ipv6`, `unifi_wlan.radius`, `unifi_setting.syslog.netconsole`) apply the default from `ModifyPlan` rather than a schema `Default`: a nested object Default carrying computed leaves can never equal the prior state, which would make the framework re-plan every other computed attribute of the resource (`firewall_zone_id`, `bandsteering_mode`, …) as `(known after apply)` on every run. A plan-level regression test (`TestPlanUnchangedConfigIsEmpty`) now guards every nested-group resource against that.
  Left flat on purpose: pairs where the prefix is itself a non-boolean leaf (`tx_power`/`tx_power_mode`, `min_rssi`/`min_rssi_enabled`, `passphrase`/`passphrase_wo`, `private_key`/`private_key_wo`, `vlan`/`vlan_enabled`), numbered slots (`priority_queue{1..4}_level`, `ntp_server_{1..4}`), groups whose leaf names would not be valid identifiers (`dtim_6e`, `minimum_data_rate_2g_kbps`), `tagged_networkconf_ids`/`tagged_vlan_mgmt` (the `*_networkconf_id(s)` family), `outlet_enabled`/`outlet_overrides`, `use_usg_*`, and the `radio_table` sub-fields.

### 🐛 Bug Fixes

- **Refreshing a resource deleted outside Terraform no longer fails with `Missing Resource Identity After Read` on OpenTofu and Terraform < 1.12.** When the controller no longer had the object, `Read` removed the resource from state without returning a resource identity. terraform-plugin-framework rejects a read response whose identity is null, even one that drops the resource, and the response identity is only pre-filled from the stored one, which CLIs without resource identity support (OpenTofu before 1.12, Terraform before 1.12) never persist. Every out-of-band deletion of `unifi_client`, `unifi_device`, and 19 other identity-bearing resources therefore broke the whole plan instead of being planned as a re-creation (the symptom of #134 again, on the removal path). The removal path now returns the identity rebuilt from the state keys when none was stored, and leaves a stored identity untouched. Resources covered: `unifi_ap_group`, `unifi_bgp`, `unifi_client`, `unifi_client_qos_rate`, `unifi_device`, `unifi_dns_record`, `unifi_dynamic_dns`, `unifi_firewall_group`, `unifi_firewall_policy`, `unifi_firewall_rule`, `unifi_firewall_zone`, `unifi_port_forward`, `unifi_port_profile`, `unifi_power_supervisor`, `unifi_radius_profile`, `unifi_radius_user`, `unifi_site`, `unifi_site_to_site_vpn`, `unifi_static_route`, `unifi_traffic_route` and `unifi_wireguard_peer`.
- **`unifi_network`: `ipv6.interface_type` no longer overwrites the controller's value on an adopted network.** The nested `ipv6` group carries no schema `Default`, but its `ModifyPlan` reproduced the old flat `ipv6_interface_type` default and re-asserted `none` on every plan whose configuration omitted the block, which brought back the overwrite v0.59.0 removed (#550): importing a network with static IPv6 again proposed `static` -> `none`. The default is now applied on create only; once a prior value exists it is kept, matching the leaf's `UseStateForUnknown` and its documentation (#544).
- **`unifi_network`: creating a network without `setting_preference` no longer fails with `api.err.InvalidPayload`.** Since v0.59.0 dropped the attribute's static default (#550) it is unknown on create, and the write path turned that unknown into an empty string, which the controller rejects. The request now omits an unset `setting_preference` so the controller applies its own default; a configured value is sent as before.
- **`unifi_setting`: Region Blocking and IPS suppression work again on controllers without the standalone `usg_geo` and `ips_suppression` documents (Network 10.0.x).** Both writes went only to the standalone keys, which those controllers reject with `api.err.Invalid`; the geo fallback also required the legacy fields to already exist on the `usg` document, which a fresh site never has. When the controller has no standalone document, `usg.geo_ip_filtering` is now merged into the `usg` setting as the flat `geo_ip_filtering_*` fields and `ips.suppression` is merged into the `ips` setting, and both are read back from there. Measured on Network 10.0.162: nested suppression is only accepted when at least one network is listed in `ips.enabled_networks`.
